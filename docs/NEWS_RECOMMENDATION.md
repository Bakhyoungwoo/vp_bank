# 04. News Recommendation

VAP의 뉴스 추천은 사용자의 검색·클릭 활동에서 관심 키워드를 추출하고, 뉴스의 키워드와 비교해 개인화된 결과를 만드는 구조입니다.

## 1. 추천 데이터 흐름

```text
사용자 뉴스 조회·검색·클릭
            ↓
Spring Boot User Activity API
            ↓
Redis 사용자별 키워드 점수
            ↓
사용자 관심 키워드 조회
            ↓
뉴스 키워드와 매칭
            ↓
점수순 추천 뉴스 반환
```

로그인 사용자는 활동 기반 추천을 받고, 활동 데이터가 없는 사용자는 기본 뉴스 목록을 제공하는 방식으로 동작합니다.

## 2. 키워드 생성과 저장

뉴스가 수집되면 AI Server가 제목과 본문을 기반으로 키워드를 추출합니다. 카테고리별 키워드 랭킹은 Redis Sorted Set에 저장해 빠르게 조회합니다.

```text
Naver 뉴스 크롤링
    ↓
KeyBERT / SBERT 키워드 추출
    ↓
뉴스별 keywords 저장
    ↓
카테고리별 Redis Sorted Set 랭킹
```

사용자가 뉴스 카드를 클릭하면 해당 뉴스의 키워드마다 사용자별 점수를 증가시킵니다.

```text
user:{userId}:keywords
    ├── AI       5.0
    ├── 반도체    3.0
    └── 금리      2.0
```

## 3. 추천 처리

추천 시 Backend는 사용자 키워드 점수와 뉴스 키워드를 비교합니다. 일치하는 키워드가 많거나 사용자 점수가 높은 키워드가 포함된 뉴스일수록 추천 우선순위를 높입니다.

```text
사용자 키워드 점수
        +
뉴스 keywords
        ↓
매칭 키워드 및 총점 계산
        ↓
추천 뉴스 정렬
```

추천 결과에는 매칭된 키워드를 함께 반환해 Frontend에서 사용자의 관심사와 추천 이유를 확인할 수 있도록 했습니다.

## 4. Redis를 사용하는 이유

- 사용자 활동 점수는 조회와 갱신이 빈번합니다.
- Sorted Set을 사용하면 점수 기반 조회를 쉽게 수행할 수 있습니다.
- 사용자별 추천 데이터가 서비스 기준 데이터와 분리되어도 됩니다.
- TTL을 적용해 오래된 활동 점수가 계속 누적되지 않도록 관리할 수 있습니다.

뉴스 원문과 북마크 같은 영속 데이터는 MySQL에 저장하고, 추천 점수와 트렌딩 키워드처럼 빠른 집계가 필요한 데이터는 Redis에 저장하도록 역할을 나눴습니다.

## 5. 주요 Backend Component

| Component | 역할 |
|---|---|
| `NewsUserActivityService` | 뉴스 클릭 키워드 점수 저장 및 사용자 관심 키워드 조회 |
| `NewsRecommendationService` | 사용자 키워드와 뉴스 키워드 매칭 및 추천 정렬 |
| `NewsTrendingService` | 카테고리별 트렌딩 키워드 조회 |
| `NewsRedisService` | 뉴스 캐시와 Redis 기반 뉴스 데이터 처리 |
| `UserNewsController` | 키워드 조회, 클릭 활동 기록, 추천 API 제공 |

## 6. 설계에서 중요하게 본 부분

- 추천 로직을 LLM에 맡기지 않고 명시적인 키워드 점수와 매칭으로 구성했습니다.
- 사용자 활동 데이터와 뉴스 원문을 분리해 각 저장소의 목적을 명확히 했습니다.
- 추천 결과에 매칭 키워드를 포함해 결과를 설명할 수 있도록 했습니다.
- 로그인 여부와 사용자 활동 유무에 따라 개인화 추천과 기본 목록을 구분했습니다.
