# 05. Financial Data Pipeline

VAP의 증시 기능은 여러 외부 금융 데이터 API에서 종목·지수·재무·뉴스 데이터를 조회하고, Frontend가 사용하기 쉬운 공통 응답으로 변환하는 구조입니다.

## 1. 금융 데이터 흐름

```text
Frontend
    ↓ 종목·지수 API 요청
Spring Boot StockController
    ↓
FastAPI Market API
    ↓
Market Service
    ├── 심볼 정규화
    ├── 캐시 확인
    ├── 요청 제한 확인
    └── Provider 호출
            ↓
      OpenBB / yfinance
            ↓
      공통 응답 변환
            ↓
Frontend
```

Spring Boot는 서비스 API와 인증·인가를 담당하고, FastAPI는 외부 금융 데이터 Provider를 호출하고 응답을 정규화합니다.

## 2. 제공 데이터

| 데이터 | 용도 |
|---|---|
| 주요 지수 | 코스피·코스닥·나스닥·S&P500 및 환율 등 시장 개요 |
| 시세·차트 | 종목별 기간별 가격과 거래량 조회 |
| 종목 검색 | 국내외 종목 검색 및 심볼 변환 |
| 기업 정보 | 종목 프로필과 기본 기업 정보 |
| 재무 정보 | 손익계산서와 재무상태 관련 데이터 |
| 관련 뉴스 | 종목별 최신 뉴스 조회 |

## 3. Provider 응답 정규화

Provider마다 심볼 규칙과 필드명이 다르기 때문에 내부에서 표준 형태로 변환합니다.

```text
사용자 입력: 005930
        ↓
심볼 정규화: 005930.KS
        ↓
yfinance / OpenBB 조회
        ↓
공통 응답
{ symbol, provider, items, updatedAt }
```

한국 종목처럼 Provider가 별도 suffix를 요구하는 경우 내부 심볼을 변환하고, 외부 응답에서는 Frontend가 사용하는 원래 종목 식별자를 함께 유지합니다.

## 4. 캐시와 요청 제한

```text
금융 데이터 요청
    ↓
Redis 캐시 확인
    ├── Hit  → 캐시 응답
    └── Miss → 요청 제한 확인 → Provider 호출
                              ↓
                         결과 캐시 저장
```

데이터 특성에 따라 캐시 시간을 다르게 적용합니다.

| 데이터 | 캐시 예시 |
|---|---:|
| 시장 개요 | 30초 |
| 검색·종목 상세 | 60초 |
| 관련 뉴스 | 120초 |
| 차트·시계열 | 300초 |
| 재무·재무상태 | 1시간 |

외부 Provider 호출에는 요청 제한을 적용해 단시간에 많은 요청이 몰리는 상황과 Provider rate limit을 완화합니다.

## 5. 장애와 데이터 품질 처리

- Provider가 반환한 값을 공통 응답으로 정규화합니다.
- 데이터가 없거나 숫자로 변환할 수 없는 값은 임의로 채우지 않고 누락 상태로 처리합니다.
- Provider 이름과 데이터 출처를 응답에 포함합니다.
- 단기 데이터는 캐시를 활용해 일시적인 Provider 지연의 영향을 줄입니다.
- OpenBB를 사용할 수 없는 경우 API는 명확한 오류 상태를 반환합니다.

## 6. AI 분석과의 연결

금융 데이터 Pipeline은 단순 조회뿐 아니라 AI 분석의 입력으로도 사용됩니다.

```text
시세·재무·관련 뉴스
        ↓
분석 모듈
        ├── 가격 변동 분석
        ├── 재무 지표 분석
        ├── 뉴스 영향 분석
        └── 종목 비교
                ↓
        계산된 지표·근거
                ↓
        AI 서술형 브리핑
```

LLM에는 원본 Provider 응답 전체가 아니라 정규화된 지표와 계산된 근거를 전달합니다. 이를 통해 데이터 조회, 수치 계산, 자연어 설명의 책임을 분리했습니다.
